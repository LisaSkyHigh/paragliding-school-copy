# Как подключить проект к GitHub (пошагово)

## Важно: что копировать в Терминал

- **Не копируйте** из этого файла строки вида **три обратные кавычки** и слово **bash** — Терминал «зависнет» с приглашением `bquote>` или `>`.
- Копируйте **только** строки команд (они начинаются с `cd`, `git` и т.д.).
- Если уже зависли: нажмите **Ctrl + C** один–два раза, введите `clear`, Enter — и начните снова.
- В корне проекта есть файл **`TERMINAL-PUSH-COMMANDS.txt`** — там те же команды **без разметки**, их проще копировать.

## Что это даёт

- Код хранится **в облаке** на GitHub.
- Можно **откатить** версию, сравнить изменения, открыть старый вид сайта по коммитам.
- Можно работать с другого компьютера: `git clone` и всё скачивается.

---

## Шаг 1. Регистрация на GitHub (если ещё нет аккаунта)

1. Откройте [https://github.com](https://github.com).
2. **Sign up** — зарегистрируйтесь (почта, пароль, имя пользователя).
3. Подтвердите почту, если GitHub попросит.

Запомните **имя пользователя** (например, `elizaveta-name`) — оно будет в ссылке на репозиторий.

---

## Шаг 2. Создать пустой репозиторий на GitHub

1. Войдите в GitHub.
2. Справа сверху **+** → **New repository**.
3. **Repository name:** например `paragliding-school` (латиница, без пробелов).
4. Выберите **Public** или **Private** (если не хотите, чтобы сайт видели все — берите Private).
5. **НЕ** ставьте галочки «Add a README», «Add .gitignore», **Add license** — у вас уже есть проект на компьютере, пустой репозиторий проще соединить с ним.
6. Нажмите **Create repository**.

Откроется страница с подсказками. Найдите блок **“…or push an existing repository from the command line”** — там будет ссылка вида:

`https://github.com/ВАШ_ЛОГИН/paragliding-school.git`

Скопируйте эту ссылку — она понадобится в шаге 4.

---

## Шаг 3. Открыть терминал в папке проекта

На Mac:

1. Откройте **Terminal** (Терминал).
2. Скопируйте **одну строку** (без кавычек вокруг всего блока — только сама команда), вставьте, Enter:

cd "/Users/elizaveta/Desktop/ИИ АГЕНТЫ/Создатель сайтов/paragliding-school"

3. Проверьте, что git уже видит проект (скопируйте строку, Enter):

git status

Если видите список файлов или «nothing to commit» — всё ок.

---

## Шаг 4. Подключить GitHub как «облако» (remote)

Один раз выполните (для вашего репозитория — скопировать **одну** строку):

git remote add origin https://github.com/LisaSkyHigh/paragliding-school.git

Если ошибка *remote origin already exists*, сначала:

git remote remove origin

Потом снова команду `git remote add origin …` как выше.

Проверка:

git remote -v

Должны увидеть строки с `origin` и вашей ссылкой.

---

## Шаг 5. Выложить код первый раз (push)

Копируйте **по одной строке** (или блоком, но без ``` и без слова bash):

git branch -M main

git add -A

git commit -m "Initial push: paragliding school site"

git push -u origin main

- GitHub спросит **логин и пароль**.  
  Пароль от аккаунта GitHub **часто не принимают** — нужен **Personal Access Token** (токен):

### Как сделать токен (один раз)

1. GitHub → иконка профиля → **Settings**.
2. Слева внизу **Developer settings** → **Personal access tokens** → **Tokens (classic)**.
3. **Generate new token (classic)**.
4. Отметьте срок (например 90 days) и право **repo** (полный доступ к репозиториям).
5. **Generate** — скопируйте длинную строку токена и сохраните в надёжном месте (покажется один раз).

В терминале при `git push`, когда спросят **Password**, вставьте **токен** (не обычный пароль от сайта).

После успешного push на странице репозитория на GitHub появятся ваши файлы.

Если `git push` пишет, что на GitHub уже есть коммиты (например, вы добавили README на сайте), выполните:

git pull origin main --allow-unrelated-histories

Сохраните файл слияния, если откроется редактор, затем снова:

git push -u origin main

## Шаг 6. Как выкладывать изменения потом

Каждый раз, когда закончили правки (по одной строке):

cd "/Users/elizaveta/Desktop/ИИ АГЕНТЫ/Создатель сайтов/paragliding-school"

git add -A

git commit -m "Кратко что сделали"

git push

## Если что-то пошло не так

- **«Permission denied»** при push — проверьте токен и что в ссылке верный логин/имя репозитория.
- **«Repository not found»** — репозиторий Private и вы не залогинены, или опечатка в URL.
- Писать в поддержку Cursor/IDE не обязательно: достаточно скопировать **полный текст ошибки** из терминала и поискать по ней или спросить ассистента.
